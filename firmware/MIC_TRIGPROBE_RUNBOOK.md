# 64ms 버퍼 단위 RMS 계측 Runbook (M5-c ⓐ, `env:mic_trigprobe`)

2026-09-23 신설. M5-c(음향 자동 트리거) 3단계 중 **ⓐ 계측**의 ④런타임 절차다.
ⓐ 계측(이 문서) → ⓑ 판정 PR(임계·디바운스·2차 세션 상한 재검토) → ⓒ 부스 투입(`other` 재학습 이후).
이 문서는 **로그를 남기는 절차**만 담는다. 임계값·디바운스 값·트리거 판정은 적지 않는다 — ⓑ 소관이다.

---

## 0. 목적

- 트리거는 「64ms 버퍼 단위」다(decisions.md 6.3). 지금까지의 실측은 **2.048초 창 집계**뿐이다
  (2026-09-23 `~/ddingdong-측정결과/2026-09-23/mic_clipshape/summary.txt` — m2 조용함 `rms_x` 85~97,
  m0 조건 A `rms_x` 304~570, m2 클램프는 전부 고립 단일 샘플(`len_max=1`)).
- **64ms 단위 분포는 미실측**이다. ⓑ에서 「연속 N버퍼」 디바운스를 오프라인으로 돌리려면
  **버퍼 단위 값이 시간 순서대로** 필요하다 → 이 env 가 그 로그를 만든다.
- 버퍼마다 raw RMS 와 **클램프 제외 RMS** 를 나란히 낸다. ToF I2C 활동 시 마이크 SD 비트 오류(6.3(n))가
  만든 고립 32767 한 개가 64ms RMS 를 끌어올리는지를 버퍼 단위로 보기 위함이다.
  계산은 `noise_stats.h` `noiseAnalyzeI16` 재사용(6.3(o) 방법론 자산) — 새 계산식 0.

## 1. 전제

- **결선 변경 금지.** 9.1(d) ToF + 6.3(a) 마이크 결선 그대로(mic_noiseprobe 세션과 같은 결선).
- ToF 는 제품과 같은 조건으로 돈다(initToF + tofJudgeFrame, prio 3 / Core 0). 부팅 줄이 `tof=ok` 여야 한다.
- 센서 앞 1.5m 는 조건별로 **같은 상태**를 유지한다. 사람이 시야에 들어오면 `[tof][StageA] presence` 줄이
  바뀐다(판정 결과는 이 env 가 쓰지 않지만 로그에 섞여 나온다).
- WiFi·서버 불필요. `secrets.h` 무관.
- 마커 입력 전 **한/영 전환을 영문으로**. 한글 입력은 마커로 인식되지 않는다(ASCII 출력 가능 문자만).

## 3. 줄 형식 (전부 `[t] ` 접두, 각 줄 ≤80B — 6.3(j) 「≤80B 62줄에서 손상 0건」)

| 종류 | 형식 | 최악 길이 |
|---|---|---|
| 데이터 | `[t] <seq> <all>,<excl>,<clip> <all>,<excl>,<clip> <all>,<excl>,<clip>` | 66B(`\n` 포함) |
| 마커 | `[t] mark=<문자> seq=<마이크가 마지막으로 만든 순번>` | 26B |
| health (5초) | `[t] hp drop=<n> gaps=<n> mstk=<B> tstk=<B\|na> q=<최고 수위>/<큐 길이>` | 67B |
| 부팅 | `[t] boot sr=… buf=… k=… q=… tof=ok\|FAIL 계측전용 판정0줄` | 69B |
| 실패 | `[t] FAIL …` / `[t] fmt_err seq=<n>` | — |

- 데이터 줄 1개 = **순번이 연속인 버퍼 1~3개**(k=3). i 번째 묶음의 순번 = `seq + i`. 버퍼 1개 = 1024 샘플 = 64ms.
- `all` = raw RMS(`rms_all`) / `excl` = 클램프(32767·−32768) 제외 RMS(`rms_excl`) / `clip` = 클램프 샘플 수.
- **줄 사이 순번 틈 = 큐 드롭**이다(순번은 드롭돼도 증가). 틈이 있으면 health 의 `drop` 도 같이 오른다.
- `[tof]` 로 시작하는 줄(tofJudgeFrame 요약 등)이 섞여 나온다. 분석 시 `[t] ` 줄만 고른다.
- 시각 = 순번 × 64ms(보드 기준) 가 1차 축이고 `-f time` 호스트 시각은 보조다(USB 전송 지연이 섞인다).
- peak 는 싣지 않는다: 클램프가 있으면 32767/32768 로 고정돼 정보가 없고, 클램프 제외 peak 는 계산식이 없다.

## 4. 마커

- 영문 출력 가능 문자 1개를 치면 `[t] mark=<문자> seq=<n>` 1줄. **어떤 문자든 같은 동작**이다(펌웨어는 키를 해석하지 않는다).
- 뜻은 사람이 붙인다. 권장 약속(로그 머리에 메모로 남길 것):
  `q` 무음 시작 / `k` 노크 구간 시작 / `c` 근접 박수 구간 시작 / `v` 말소리 구간 시작 / `e` 구간 끝.
- 마커 순번은 「키를 친 순간 마이크가 마지막으로 만든 버퍼」다. 키 입력~보드 수신 지연(수~수십 ms)만큼 늦을 수 있다
  → 구간 경계는 ±1~2버퍼 오차로 읽는다.

## 5. ④런타임 프로토콜 골격 (조건마다 시작·끝 마커)

| 순서 | 조건 | 시작 마커 | 길이·횟수 | 끝 마커 |
|---|---|---|---|---|
| 1 | 무음(대화 없음, 공조음은 세션 내내 동일) | `q` | 60초 | `e` |
| 2 | 노크(문/책상, 평소 세기) | `k` | 약 3초 간격 10회 | `e` |
| 3 | 근접 박수(마이크 30cm 안팎) | `c` | 약 3초 간격 10회 | `e` |
| 4 | 말소리(평소 대화 크기, 1m) | `v` | 30초 | `e` |
| 5 | 무음 재측정(드리프트 대조) | `q` | 60초 | `e` |

- 조건 사이 10초 이상 쉰다(앞 조건의 잔향이 다음 구간 첫 버퍼에 섞이지 않게).
- 세션 끝에 health 줄 2개 이상이 찍힐 때까지(10초) 기다린 뒤 모니터를 닫는다.
- 결과 해석(임계·디바운스 N 산출)은 **ⓑ 판정 PR** 에서 한다. 이 세션에서는 로그를 보존하는 것까지만.

## 6. 정지 트리거 (보고 후 사용자 판단)

- a) 부팅 줄 `tof=FAIL` 또는 health `tstk=na` — ToF 가 안 돈다 = **제품 조건이 아니다**. 이 세션 로그를 ⓑ 입력으로 쓰지 말 것.
- b) health `drop` > 0 또는 데이터 줄 순번 틈 — 큐가 넘쳤다. 원인(loop 정체)을 먼저 본다. `q` 가 32/32 에 닿았는지 같이 기록.
- c) health `gaps` 증가 — i2s_read 실패(DMA 오버런 성격). 그 구간은 쓰지 말 것.
- d) `[t] fmt_err` 1줄이라도 — 값이 필드 폭 도메인을 벗어났다(설계상 도달 불가). 설계 전제가 깨진 것이므로 즉시 보고.
- e) `[t] FAIL` — setup 실패. 부팅 로그의 `[BOOT] …실패` 줄을 같이 보고.
- f) `[t] ` 줄 중간이 잘리거나 두 줄이 한 줄로 붙음 — 6.3(j) 줄 무결성 전제가 깨졌다(아래 7-1 한계 참조).

## 7. 호스트 단위 검증 (하드웨어 없이 언제든 재실행)

```
c++ -std=c++17 -Wall -I firmware/include -o /tmp/tlt firmware/tools/trig_line_test.cpp && /tmp/tlt
```
`firmware/include/trig_line.h`(보드가 쓰는 **같은 파일**) + `noise_stats.h` 를 include 한다(복사 아님). 2026-09-23 **74 checks OK**.

- T1 최악 입력(전 필드 최댓값 × 3, 순번 4294967295→0→1 랩) → 길이 = 헤더 산술 `TRIG_LINE_WORST`(66) 정확 일치 · ≤80. 도메인 밖·작은 버퍼·빈 입력 가드.
- T2 왕복: 합성 1024 샘플(±300 배경 + 고립 32767 1개) → `noiseAnalyzeI16` → 포맷 → 테스트 내 파서로 되읽기 → 값·순번 일치, `rms_all > rms_excl`, `clip_n = 1`.
- T3 순번 연속: 10개 → 4줄 전수 되읽기 / 드롭 틈(5,6,_,8,9)에서 줄 끊김 / uint32 랩.

negative control(각각 **반드시 실패**해야 통과). 헤더를 **사본에 복사해 변형**하고 `-I <사본 dir> -I firmware/include` 로 컴파일한다.
4단계 = ① 변형 적용(`diff` 1줄 이상) ② baseline 통과 ③ 변형 실패 ④ 사본을 원본으로 되돌리면 다시 통과 + 원본 md5 무변경.

| # | 변형 (`trig_line.h` 1건 치환) | 깨는 불변식 | 2026-09-23 결과 | 검출 위치 |
|---|---|---|---|---|
| NC-1 | 묶음 출력 인자 `rms_all, rms_excl` → `rms_excl, rms_all` | 버퍼별 값이 제자리에 실린다 | **검출** | T2 `back.rms_all == in.rms_all` (클램프 입력이라 두 값이 갈린다) |
| NC-2 | 순번 `"[t] %u"` → `"[t] %011u"` | 최악 길이 = 헤더 산술 | **검출** | T1 `len == TRIG_LINE_WORST` (66→67. 「≤80」만 봤으면 미검출) |
| NC-3 | 묶음 루프 `i < take` → `i + 1 < take` | 버퍼 누락 0 · 순번 연속 | **검출** | 전체 실행 시 T1 길이 단언이 먼저. T1 제외 사본 → T2 `back.size() == in.size()`, T3 단독 사본 → T3 `back.size() == in.size()` 에서도 각각 검출 |

## 7-1. 한계 (제품과 다른 조건 · 미확인)

- **WiFi off** — 제품(mic_uplink / enrich_uplink)은 WiFi 가 켜져 있다. RF 활동이 마이크 잡음에 주는 영향은 이 로그에 없다.
- **링버퍼 없음 · 업링크 없음 · 2차 녹음 없음** — 마이크 태스크가 하는 일이 제품보다 적다(링 적재·스냅샷 복사 대신 분석·큐 전송).
  CPU 경합 조건이 제품과 같지 않다.
- 줄 섞임: HWCDC `write` 는 호출 1회를 뮤텍스로 감싼다(설치 코어 2.0.17 `HWCDC.cpp` 확인). 이 env 는 줄 1개를 `write`/`printf` 1회로 내므로
  태스크 간 줄 **중간** 섞임은 없다고 본다 — **논증, 미실측**. `[t] FAIL …` 은 `println`(write 2회)이지만 loop 만 쓴다.
- HWCDC 쓰기가 타임아웃(호스트가 안 읽음)하면 그 줄은 버려질 수 있다 — 버려진 데이터 줄은 **순번 틈**으로 보이지만 health `drop` 은 오르지 않는다
  (큐 드롭이 아니라 USB 쪽 손실). 순번 틈 ≠ drop 증가면 이 경우다.
- 64ms 경계는 DMA 버퍼 경계다. 노크 한 번이 두 버퍼에 걸칠 수 있다(어택 위치에 따라 값이 나뉜다).
