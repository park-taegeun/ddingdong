# 마이크 잡음 근본원인 진단 Runbook (PoC-(45), `env:mic_noiseprobe`)

2026-09-11 신설. 대상 = **ToF 측정 중 조용한 2초 스냅샷의 peak 32767~32768 클립**(PR #53 댓글 「알려진 문제 1」).
이 문서는 **관측 절차와 판정표**만 담는다. 해결책(재배선·필터·I2C 속도 확정·태스크 재배치)은 범위 밖이며,
판정표도 「지지 / 기각」까지만 적는다 — 무엇을 고칠지는 결과를 본 사람이 정한다.

---

## 0. 이 세션이 증명하려는 것

**배경(실측, 2026-09-11 `~/ddingdong-측정결과/2026-09-11/ToF_meta_uplink_runtime.log`)** — 같은 자리·결선·수 분 차이, 펌웨어만 교체:

| 펌웨어 | ToF | 조용한 스냅샷 | peak | rms |
|---|---|---|---|---|
| `mic_uplink` (PR #53) | 측정 ON | 6회 | **32767 ×5, 32768 ×1** | 455~636 |
| `main b3414a4` | 전원만, 측정 OFF | 3회 | 412~464 | 95~96 |

- 32767 / 32768 은 `mic_common.cpp convertMicRawToInt16` saturation 가드의 두 클램프값(`INT16_MAX` / `|INT16_MIN|`)과 **정확히 일치**한다 → 관측값은 "큰 소리"가 아니라 **가드가 잘라낸 raw 이상치**다(코드 인용 + 실측 일치).
- "원인 = ToF 측정 동작"까지는 실측이다. **그 안의 기전은 미분리** — 아래 셋은 전부 **가설(논증)**이다.

| 가설 | 기전 | 근거 성격 |
|---|---|---|
| **H1** I2C 누화 | SCL(GPIO6, 브레드보드 J10)과 마이크 SD(GPIO7, B10)가 **같은 10번 열**(중앙 홈 건너편) + 마이크 M/F 점퍼 공중 부양(6.3(a) / 9.1(d) 결선표) → SCL 엣지가 SD 로 유입 → I2S 비트 오류 → 가드 클램프 | 논증 |
| **H2** 센서 동작 전원 | VL53L5CX 측정(VCSEL 발광) 전류가 공유 3V3 를 흔든다. I2C 트래픽과 무관 | 논증 |
| **H3** 소프트웨어 경합 | tofTask(Core 0, prio 3) ↔ micTask(Core 0, prio 4). 단 `gaps=0` 실측이라 DMA 오버런은 아님 | 논증 |

이 env 는 **한 번에 한 변수만** 바꾸는 모드 5개로 셋을 가른다.

## 1. 전제 (전부 지켜야 결과가 비교 가능하다)

- **결선 변경 금지.** 9.1(d) ToF 6가닥 + 6.3(a) 마이크 6가닥 그대로. 재배선은 해결책이므로 이 세션에서 하지 않는다 — 배선을 건드리면 A/B 의 "같은 결선" 전제가 깨져 m0 대조군이 무효가 된다.
- **조용한 환경.** 사람 대화 없음. 에어컨·공조음은 상시 포함되어도 되지만 세션 내내 **동일**해야 한다(6.3(j) "조용한 랩실 ≠ 완전 무음" 주의 승계).
- **센서 앞 1.5m 빈 공간.** ToF 판정(tofJudgeFrame)은 로그하지 않지만 제품과 같은 CPU 부하를 위해 호출한다. 시야에 사람이 들어오면 발광/적분 조건이 바뀔 수 있어 H2 비교가 흐려진다(9.2(e) 시야 오염 주의 준용).
- WiFi·서버 불필요. `secrets.h` 무관.
- 부팅 직후 모드 = **m2**(현행 재현). 모드를 바꾸면 반드시 `[noise][mN] rng=… ok=1` 확인 줄이 뜬다. `ok=0` 이면 그 모드 결과는 무효 — 8절.

| `1` | m1 | ON | **OFF** (버스 idle) | 400k(무관) | – | m2 대비 읽기 제거 |
| `2` | m2 | ON | ON | 400k | Core 0 | **현행 재현** (= mic_uplink 조건) |

| `h` | – | 키 요약 1줄 | | | | |

**구현 가능 여부 (Step 0 대조 결과)** — 5개 전부 구현. 단 m1 은 전제가 하나 있다:

| 모드 | 판정 | 근거 |
|---|---|---|
| m0 | 가능 | SparkFun `stopRanging()`/`startRanging()` 런타임 호출 = ULD `vl53l5cx_stop_ranging`(레지스터 쓰기 + MCU stop 폴링, `vl53l5cx_api.cpp:551~`) / 재시작 지원 |
| m1 | 가능 **(전제 = 논증)** | ULD `vl53l5cx_check_data_ready` 는 호스트가 0x0 4바이트를 읽어 streamcount 변화만 보는 **호스트측 폴링**이고 ack 쓰기가 없다(`vl53l5cx_api.cpp:591~608`) → 읽지 않아도 센서는 autonomous 로 계속 측정한다고 **논증**. ★ 실측 확인 = 5절 ③ (m1→m2 첫 프레임 `sc a->b` 전진) |
| m2 | 가능 | `initToF()`(tof_common.cpp) 그대로 = 400k / 8x8 / 15Hz / startRanging |
| m3 | 가능 | `Wire.setClock()` = esp32-hal-i2c `i2cSetClock` → `i2c_hal_set_bus_timing` **라이브 재설정**(재init 없음, core 2.0.17 실물 grep) |
| m4 | 가능 | tofTask 를 Core 0/1 에 하나씩 미리 띄우고 활성 코어만 전환(태스크 삭제·재생성 없음) |

모드 전환 확인 줄(예): `[noise][m3] rng=1 poll=1 i2c=100k core=0 ok=1 sc=131`
- `rng` 측정 중 / `poll` 호스트 읽기 중 / `i2c` 현재 클럭 / `core` 폴링 코어 / `ok` 전환 API 전부 성공 / `sc` 마지막 성공 프레임 streamcount.
- 이어서 폴링 모드(m2~m4)면 첫 프레임에 `[noise][mN] first frame core=C sc a->b` 1줄.

## 4. 스냅샷 로그 7줄 (`s` 1회당, 각 줄 ≤80B — 6.3(j) 시리얼 손상 0 구간)

```
[noise][m2] snap#1 n=32768 peak=32767 rms=512 rms_x=101
[noise][m2] clip=37(+20/-17) burst=9 len_max=6 first=12345
[noise][m2] gap_ms n=8 min=67 mode=67 max=1401 tof_mult=7/8
[noise][m2] raw bad=37 low6nz=37 iso_hi=35 tz=6
[noise][m2] raw ex 40000F40 BFFF0F00 40001000 C0000F80
[noise][m2] tof_rd=31 dt_ms min=0.0 avg=1.2 max=3.1 in=8/9
[noise][m2] slot_dt_us min=63990 max=64010 gaps=0 stk=2296
```

| 줄 | 필드 | 뜻 |
|---|---|---|
| L1 | `peak` | max \|int16\|. **32767 또는 32768 = 클램프 존재** |
| | `rms` / `rms_x` | 전체 RMS / **클램프 샘플 제외** RMS. `rms_x` 가 m0 값(≈95~119)과 같으면 클램프 **외** 구간은 깨끗 |
| L2 | `clip=(+/-)` | 클램프 샘플 수(+32767 / −32768 각각) |
| | `burst` | 클램프 무리 수(간격 < 16 샘플 = 1ms 면 같은 무리). `len_max` 가장 긴 무리 폭(샘플). `first` 첫 클램프 인덱스 |
| L3 | `gap_ms` | 무리 시작→다음 무리 시작 간격(반올림 ms) 최소/최빈/최대. `tof_mult=a/b` = 간격 b개 중 **66.7ms 정수배(±10%)** a개 |
| L4 | `raw bad` | 가드 이전 raw 중 int16 를 벗어나는 샘플 수(= 가드가 잘랐을 수, clip 과 같아야 정상) |
| | `low6nz` | bad 중 **하위 6비트 ≠ 0**. INMP441 정상 데이터는 tz=6(하위 6비트 항상 0, 6.3 실측) → 0 이 아니면 음향이 아니라 **비트 오류** 정황 |
| | `iso_hi` | bad 중 "상위 비트 1개만 뒤집힌 모양"(부호 아래 첫 상이 비트 1개 뒤에 부호 비트 8개 연속). 큰 소리는 이 모양이 잘 안 나온다 |
| | `tz` | 스냅샷 전체 OR 누적의 trailing zeros. 6 이면 정렬 정상(6.3), 그 미만이면 하위 비트가 어딘가에서 섰다 |
| L5 | `raw ex` | bad 샘플 앞 4개 hex(육안) |
| L6 | `tof_rd` | 스냅샷 시점 보유한 ToF 읽기 창 수(최근 64건). `dt_ms` = 각 버스트 시작 시각 → 가장 가까운 ToF **I2C 읽기 창** [isDataReady 직전, getRangingData 직후] 까지 거리. `in=a/b` = b 버스트 중 창 **안**(거리 0) a개 |
| L7 | `slot_dt_us` | 연속 슬롯의 i2s_read 반환 시각 차. **64000 ± 수백 µs 가 정상.** 크게 벗어나면 L6 시각 상관은 신뢰 불가(i2s_read 반환 = DMA 완료 + 큐 대기 상한) |
| | `gaps` / `stk` | i2s_read 실패 누적(0 이어야) / micProbeTask 스택 최저 여유 |

⚠️ L6 의 시각은 **상한 근사**다: 샘플 시각 = 슬롯 끝 시각 − (1024−k)×62.5µs 로 역산하며, 슬롯 끝 시각엔 태스크 스케줄 지연이 섞인다. `slot_dt_us` 가 64000 근처일 때만 `in`/`dt_ms` 를 근거로 쓴다. 이 한계는 코드로 못 없앤다(DMA 완료 시각을 ISR 없이 얻을 수 없음) — **가능성·근거 보고**: 충분 조건이 아니라 **정합 여부** 확인용.

## 5. 절차 (모드별 조용한 스냅샷 3회)

① 부팅 → `ring filled` 확인 → 5초 대기(m2 안정) → `s` ×3 (각 3초 간격) → 7줄×3 기록.
② `0` → 확인 줄 `ok=1` → 5초 대기 → `s` ×3.
③ `1` → 확인 줄 → 5초 대기 → `s` ×3. 그 다음 `2` 를 눌러 **`first frame … sc a->b`** 의 a≠b 를 확인해 기록(a = m1 진입 시 sc, b = 첫 프레임 sc. **전진했으면 m1 동안 센서가 계속 측정했다는 실측 증거** = m1 전제 확인. 같으면 m1 결과를 "센서 정지 상태"로 재해석해야 한다).
④ `2` → `s` ×3 (①과 재현되는지).
⑤ `3` → 확인 줄 `i2c=100k` → 5초 → `s` ×3.
⑥ `4` → 확인 줄 `core=1` + `first frame core=1` → 5초 → `s` ×3.
⑦ 마지막에 `2` → `s` ×1 (세션 중 환경 드리프트 확인 — ①·④와 같은 자릿수여야 한다).

**기록 표 양식** (스냅샷 1회 = 1행. 7줄에서 옮겨 적는다):

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| m2 | 1 | | | | | | | | | | | | | | | | |
| … | | | | | | | | | | | | | | | | | |

## 6. ★ 판정표 (가설 → 기대 패턴). **지지 / 기각까지만** — 해결책은 적지 않는다

전제: m0 3회가 전부 `clip=0`, `rms_x≈rms≈m0 기준선`(A/B 실측 95~96 자릿수)이어야 이하가 성립한다. m0 에서도 클립이 나오면 원인은 ToF 측정 밖(§9-a 정지·보고).

| 관측 패턴 | 읽는 법 |
|---|---|
| m0·m1 깨끗(clip=0) **&** m2 오염 | 클립은 **호스트 I2C 트래픽이 있을 때만** 발생 → H1 또는 H3 지지, H2 기각 |
| m1 오염 | 호스트가 버스를 안 만지는데도 발생 → **H2(센서 동작 전원) 지지**, H1·H3 단독으로는 설명 불가. (m1 전제 `sc` 전진 확인 필수) |
| m3 `clip`·`burst` 가 m2 대비 **뚜렷이 감소**(같은 자릿수 아님) | 클립 수가 SCL 엣지 수/속도에 비례 → **H1 지지**. (100k 에서 트랜잭션은 길어지고 엣지 수는 같으므로, 감소는 "엣지 기울기·속도" 의존을 뜻한다 — 논증) |
| m3 ≈ m2 | 클럭 무관 → H1 의 "엣지 속도" 변형은 약해지나 H1 자체 기각은 아님(엣지 **수**는 같다) |
| m4 ≈ m2 | 코어를 바꿔도 같음 → **H3 기각** |
| m4 뚜렷이 감소/소멸 | Core 0 동거가 조건 → **H3 지지** (H1·H2 는 코어와 무관해야 하므로 약화) |
| `gap_ms` 최빈/다수가 66.7ms 배수(`tof_mult` 비율 높음) | 클립이 **ToF 프레임 주기에 동기** → I2C 읽기(폴링 성공 프레임) 또는 발광 주기와 결합. m1/m2 비교로 어느 쪽인지 가른다(m1 에서도 배수면 발광 동기 = H2 쪽) |
| L6 `in` 비율 높음 + `slot_dt_us` 정상 | 클립이 I2C 읽기 창 **안**에 몰림 → H1 정합(H3 도 배제는 안 됨) |
| L4 `low6nz > 0` 또는 `iso_hi ≈ bad` | raw 가 **음향 파형이 아니라 비트 오류** 모양 → 전기적 유입(H1) 정합. 진짜 큰 소리(포화 음향)라면 low6nz=0 · iso_hi≈0 · 파형 연속 |
| L4 `tz < 6` | 하위 비트까지 섰다 → I2S 라인 자체에 비트 오류 = H1 정합 |
| `rms_x ≈ m0 rms` | 클램프 샘플만 제외하면 배경은 정상 → 잡음이 **연속 노이즈 플로어 상승이 아니라 이산 사건** |

⚠️ 한 행만으로 결론내지 말 것. 최소 m0·m1·m2 세 모드의 교차로 H2 를 먼저 가르고, m3·m4 로 H1/H3 을 나눈다. 판정 결과는 decisions.md 에 "지지/기각 + 어느 행이 근거" 형식으로 등재하고 **해결책은 별도 결정**으로 남긴다.

## 7. 호스트 단위 검증 (하드웨어 없이 언제든 재실행)

```
c++ -std=c++17 -Wall -I firmware/include -o /tmp/nst firmware/tools/noise_stats_test.cpp && /tmp/nst
```

## 9. 정지 트리거 (보고 후 사용자 판단)

- a) **m0 에서도 clip > 0** — "원인 = ToF 측정" 실측 전제와 충돌. 배경(마이크 자체·전원·다른 소음원)을 먼저 의심해야 하며 이 Runbook 의 판정표는 무효.
- b) `ok=0` 이 재부팅 후에도 반복 — 모드 전환 수단 자체가 신뢰 불가.
- c) m1→m2 `sc a->b` 에서 a == b — m1 동안 센서가 측정을 멈췄다는 뜻이라 m1 = m0 과 같은 조건이 되어 H2 격리 불가(설계 전제 붕괴 → m1 재설계 필요, 이 문서 범위 밖).
