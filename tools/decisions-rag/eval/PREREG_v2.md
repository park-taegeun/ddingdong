## 실험 (각각 기준선 대비 한 변수)

- **E3 가상 문단(HyDE)** = 조건 `hyde`. 질문마다 답변 모델(`gpt-4.1-mini-2025-04-14` · 온도 0 · seed = 평가 설정 `random_seed`)이 아래 E3 프롬프트로 가상 문단 1개를 쓴다. 검색 벡터 = 원 질문 임베딩과 가상 문단 임베딩의 평균. 인덱스 · 청킹 · 상위 k는 기준선 그대로.
- **E4 제목 목록 재작성** = 조건 `rewrite`. 같은 모델 · 온도 · seed로, 아래 E4 프롬프트에 decisions.md 제목 목록을 넣어 검색 질의 한 줄을 쓴다. 검색 벡터 = 원 질문 임베딩과 재작성 질의 임베딩의 평균. 제목 목록 = 원문의 `##` · `###` 제목 줄과 소절 제목(`**(x) …**`)을 문서 순서대로 모으고 각각 80자에서 자른 것. 제목은 문서 자체에 있는 정보이며 평가셋 정보가 아니다.
- **E5 큰 임베딩** = 설정 `configs/e5_large.json`(`baseline.json`과 `name` · `embed_model` = `text-embedding-3-large` · 임베딩 단가 칸만 다름) + 조건 `dense`. 청킹은 기준선 그대로.
- 각 조건의 `gold_removed` 변형으로 평가기를 자기 검증한다(정답 청크를 빼면 적중 0 — 아니면 실행 실패).
- 가상 문단 · 재작성 질의는 검색 평가 때 한 번 만들어 repo 밖 실행 폴더에 남기고, 답변 단계의 검색은 그것을 그대로 쓴다(다시 생성하지 않는다).
- 답변 단계의 프롬프트에 들어가는 질문은 원 질문이다. 답변 상위 k = 5(기준선과 같음).

## 채택 규칙

**1단계 — v1 검색(답 있는 25문항).** 통과 = 전체 Hit@3 ≥ 기준선 + 2(즉 8 이상) · 어떤 유형도 Hit@3가 2문항 이상 줄지 않음.
- 통과가 둘 이상이면 하나만 다음 단계로 보낸다: 전체 Hit@3가 높은 쪽 → 같으면 MRR@10이 높은 쪽 → 같으면 E5 · E3 · E4 순(질의마다 LLM 호출이 없는 쪽 먼저).
- 통과가 없으면 여기서 끝낸다. 답변 · H1 답변은 돌리지 않는다.

**2단계 — 확인(후보 1개).**
- H1 검색: 후보의 Hit@3 ≥ 기준선의 Hit@3(H1 답 있는 12문항).
- 답변: 후보로 v1 30문항 + H1 15문항, 기준선으로 H1 15문항을 돌려 한 블라인드 시트(60행)로 채점한다. 통과 = 후보 v1 정답 수 ≥ 9 · 후보 H1 정답 수 ≥ 기준선 H1 정답 수.

**채택** = 1 · 2단계 모두 통과. 「채택」은 사전 등록 규칙 통과만 뜻한다 — 기본 설정 반영은 별도 판단이다.
- 조합(예: E3 + E5)이나 다른 값 시도는 탐색적이며 채택 판정에 쓰지 않는다.
- 표본이 작다(v1 검색 25 · H1 검색 12) — 결과는 방향 판단용이며 일반화 주장을 하지 않는다.
